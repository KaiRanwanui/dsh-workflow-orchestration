# 技能：设计准备/环境初始化（sys-design-init）

## 任务目标
进行项目空间的环境初始化，完成开展产品的系统分析和设计活动的各项准备，包括设计活动所需的知识、工具、版本控制、必要输入。产出**环境准备报告**，记录工作环境各类约束，供后续任务确认工作环境。

## 输入
- `prd/PRD.md`：产品需求定义（工作空间根）。

## 执行步骤

1. **项目目录检查/创建**：以工作空间根为项目根，逐一检查以下 12 个目录，缺则创建（空目录写入 `.gitkeep` 占位）：
   - `prd/`（PRD 输入件）
   - `req_spec/`（需求分析交付件）
   - `design_spec/`（设计交付件）
   - `reports/`（关键报告）
   - `knowledge-base/product-kb/business/`、`knowledge-base/product-kb/design/`、`knowledge-base/product-kb/architect/`（产品级知识：业务/设计/架构）
   - `knowledge-base/version-kb/`（版本级知识）
   - `knowledge-base/personal-kb/`（个人知识）
   - `knowledge-base/dfx-kb/`（专业领域知识）

2. **工具齐备性检查与安装**：检查以下工具是否在环境中安装可用，如果不可用，则进行安装和配置。无法完成安装并可用，则记「待装」并判环境不就绪。
   - git
   - python3


3. **知识准备（本版本占位）**：确认 `knowledge-base/` 目录树就位（第 1 步已建）；当前版本知识文件允许为空，须在报告**显式声明**「知识文件为空；知识索引未构建（占位）」。从指定位置下载/复制与知识索引构建属后续扩展。

4. **输入件检查**：检查 `prd/PRD.md` 存在、非空、含一级标题且至少一个功能相关小节（入口条件）；通过后提取需求简报：产品主题、产品定位、功能点清单与计数。

5. **git 建仓并初始化提交**：
   - 在工作空间根目录生成根 `README.md`（一句话项目说明 + 目录结构清单）
   - 为工作空间初始化git仓，`.gitignore` 排除隐藏目录（`.gitkeep` 保留），完成目录骨架加入 git 并完成初始提交，记录仓根路径与首提交 hash。
   - 若已有 git 仓：记录现状、补齐缺失的 `.gitignore`/`README.md`，说明本次提交或无变更。

6. **输出环境准备报告**：汇总上述全部结果，按下方结构写入任务输出文件。

## 输出文档结构（环境准备报告）
- `## 环境就绪声明`：一句话总结——六步全过写「就绪」；任一步不通过写「不就绪」并列明原因。
- `## 项目目录结构`：12 个目录逐一列出路径、用途与状态（已存在/已创建）。
- `## 工具检查`：每个工具各一条——版本号或探测结果、安装动作（如有）、结论（可用/待装）。
- `## 知识库状态`：目录树就位情况 + 显式声明「知识文件为空；知识索引未构建（占位）」。
- `## 输入件检查（PRD）`：状态（OK/不 OK）+ 检查明细 + 需求简报（主题/定位/功能点清单与计数）。
- `## Git 仓初始化`：仓根路径、`.gitignore`/`README.md` 状态、首提交 hash（或已有仓说明）。

## 输出要求
- 将环境准备报告写入调用方指定的输出文件。
- 全文 Markdown、中文；各小节不得留空。
- 文件写入后，回复一行：`DONE: <输出路径>`。
- 除报告输出文件、第 1/5 步声明的目录与文件外，不要创建任何其他文件。
