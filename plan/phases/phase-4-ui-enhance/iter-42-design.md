# Iter-42 设计（v2 重定案）— DAG 数据源重构：结构=实例文件，状态=执行叠加

- **阶段**：阶段 4
- **日期**：2026-09-19
- **状态**：**待用户确认后编码**（本版替代 iter-42-design.md 初版「一键 Reset 生效流」——用户指正：同步视图不是 Reset，Reset 会触发归档语义不应挪用）

---

## 1. 需求正解（用户定义）

> DAG 的结构应该始终跟实例文件一致（所见即所得）；DAG 上的状态跟实际执行状态一致。

即 DAG 的两个图层彻底分离：

| 图层 | 数据源 | 更新时机 |
|---|---|---|
| **结构层**（节点/边/分组） | **instance.yaml**（定义） | 编辑保存即刷新（无需任何"生效"操作） |
| **状态层**（颜色/脉冲/门禁结果/迭代行） | state.json 执行任务（按 id/组匹配叠加） | 2s 状态轮询（现状） |

## 2. 现状与差距

现状 DAG 整体渲染自 **state.json**（begin 时固化的执行快照）——编辑保存后结构不变，直到 Reset（且面板 Reset 流程伴随归档/解绑语义，不能当刷新用）。这就是"改了定义 DAG 没变"的架构性根因。

## 3. 方案（DagCanvas 输入管线重构，纯 Client）

| # | 改动 | 说明 |
|---|---|---|
| 1 | 结构源切换 | DagCanvas 新增定义态输入：编辑器保存/加载已拉的 instance.yaml（`/wf/instance-yaml` 的 rawYaml.tasks）→ 构建节点图：普通任务=任务节点；`type: loop`/`concurrent` =组节点（成员未执行时显示「⏳ 等待 items」占位，复用现有 placeholder 形态）；dependsOn → 边。**不再依赖 state.tasks 提供结构** |
| 2 | 状态叠加 | state.tasks 按 id 精确匹配 → status/gateResult/gateNote/脉冲；组节点：state 中 `_loopGroup/_concurrentGroup` 匹配的展开迭代 → 组节点成员行（现有成员行渲染复用）；state 无对应任务的节点 = 未执行态（灰） |
| 3 | 定义新增/删除任务 | 新增（state 无）→ 未执行态节点即刻出现；删除 → 节点即刻消失（其历史执行记录留在 state，不展示） |
| 4 | 一致性提示 | 结构=最新定义恒成立（所见即所得）；当 state 中存在「定义中已不存在的任务」时，状态栏黄色小徽标「执行状态为上一轮 · Reset 后对齐」——提示执行态与定义的差异，不阻断 |
| 5 | Reset 语义不动 | Reset 仍是「清空执行、重新开始」的执行操作（归档等既有行为不变）；本迭代**不新增任何"生效"按钮**——因为保存即所见即所得，无需生效动作 |

## 4. 明确不做 / 语义边界

- **不做服务端改动**：reset/归档/begin 语义全部保持现状；本迭代纯客户端渲染重构。
- **不改执行语义**：修改定义不影响正在运行/已完成的执行；Reset 才重新执行（用户已明确）。
- 编辑器与 DAG 共用同一次 `/wf/instance-yaml` 拉取（编辑保存后的 load 已覆盖）。

## 5. 验证标准

- [ ] 单测全绿；产物级核验
- [ ] 真机六条：①STOPPED 实例编辑保存（加/删任务、改 dependsOn）→ DAG **立即**反映新结构（不切页签、不 Reset）②已有任务的执行状态叠加正确（颜色/门禁角点/脉冲）③loop/concurrent 组节点与成员行随 state 展开正确 ④定义新增任务显示未执行态、删除任务消失 ⑤出现「执行状态为上一轮」徽标场景与 Reset 后对齐 ⑥RUNNING 脉冲/自动跟随（Iter-40）不回归

## 6. 工作量估计

**约 1.5 人天**（定义→图构建 0.5 + 状态叠加合并 0.4 + 组/占位/徽标 0.3 + 回归 0.3）。较初版（0.75 天）增加，因这是渲染数据层重构而非交互编排。
