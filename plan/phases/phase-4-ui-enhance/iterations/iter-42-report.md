## 1. 需求正解（用户定义，替代初版「一键 Reset 生效流」）

> DAG 的结构应该始终跟实例文件一致（所见即所得）；DAG 上的状态跟实际执行状态一致。
> 同步视图不是 Reset——Reset 会触发实例归档，不应挪用。

## 2. 交付件

| # | 交付件 | 实现 |
|---|---|---|
| 1 | DAG 数据源重构 | 结构层=instance.yaml 定义任务（编辑保存即刷新，所见即所得）；状态层=state 任务按 id/组匹配叠加（颜色/门禁角点/脉冲/迭代行） |
| 2 | 定义态节点 | 定义新增任务即刻出现（PENDING 态）；loop/concurrent 组未执行时合成哨兵占位（复用既有占位渲染「等待 items」）；定义删除的任务即刻消失 |
| 3 | 「上一轮」徽标 | state 残留任务（定义已删除）>0 → DAG 上方黄色徽标「有 N 个任务的执行状态属上一轮定义 · Reset 后对齐」 |
| 4 | openSkillView 归一 | 编辑页技能查看改传原始路径+workspaceRoot（服务端两级链，与详情卡同语义）；列表仅作下拉数据源（Iter-41 遗留闭环） |

## 3. 语义边界

- Reset 语义完全不动（含归档行为）——回归「清空执行重新开始」的执行操作
- 服务端零改动；不改执行语义（修改定义不影响运行中/已完成的执行）
- 无 state 的 CREATED 实例仍维持现状（不显示 DAG）——定义态 DAG 全量前移不在本迭代范围
