## 1. 背景与目标

编辑器（Iter-28）目前只有**双栏表单态**（参数区 + 任务表单）。表单态对「精确控制定义文本」的场景不便：字段覆盖不全（Iter-36 补）、批量调整繁琐、无法直接看到 YAML 原貌。本迭代给编辑器增加 **YAML 源码模式**，与表单态互切，保存走既有语义校验关口。

**做完后达成什么**：编辑器可一键切换到 YAML 源码视图，直接编辑定义全文，保存时被既有语义校验关口拦截/放行，行为与表单态完全一致。

**不做什么**：YAML 高亮/格式化（纯 textarea，语法着色不在本迭代）；params 编辑（Iter-37）；items-from 等表单字段补全（Iter-36）。

## 3. 技术方案

### 3.0 已确认决策（用户 09-17）

源码态默认关闭（默认表单态，点「源码」切换）；textarea 占满编辑区（内滚动）。

### 3.0a 创建弹窗去除 yaml 编辑（交付件 4）

- `tplSel.startsWith('tpl:')` 分支：payload 改为**仅 `workflowPath`**（不再读 yamlText/不提交 workflowText）；弹窗中模板 yaml textarea 删除，改为模板说明性展示（名称+描述，只读）。
- `custom` 分支保留（路径直填，非 yaml 编辑）。
- 收益：创建语义收敛为「模板引用」（presetCopy/目录锚点/静态文件复制天然生效，无 yaml 漂移可能）；编辑职责单点化到实例编辑器。

### 3.0b 技能全文只读浏览（交付件 5）

- `mkSkillSelect` 增加可选「查看」按钮：值非空时可用 → `GET /wf/skill?path=<绝对路径>`（既有路由）→ 只读弹层（等宽、内滚动、关闭按钮）；fetch 失败弹层内展示错误。
- 应用点：processor 与 gateChecker 两处下拉旁。
- 只读边界：skills 不物化进实例（R4 设计），无本地副本可写；编辑技能属预定义资产治理，不在实例编辑器范畴。

### 3.1 两态模型

- **表单态**（现状，默认）：双栏表单，改动经表单字段收集 → POST。
- **源码态**（新）：textarea 展示 GET 返回的 `text`（strip 后原文）；用户编辑 → 「保存」直接 POST 该文本。
- **切换规则**：单态内改动未保存时切换到另一态 → **弹确认**（「有未保存改动，切换将丢弃」）；无改动直接切。两态不共享未保存状态（各自独立编辑缓冲）。
- **保存后**：成功 → 重新 GET 刷新两态缓冲（表单态与源码态都回到已保存内容）；失败 → 留在当前态，展示错误清单。

### 3.2 权限与阶段门控（沿用服务端矩阵）

- `editable.definition=false` 或 `readonlyAll` → 源码态 textarea 只读（可看不可改），保存按钮禁用；服务端闸门照旧兜底（双保险）。
- 运行中（RUNNING）实例：按既有矩阵（definition=false）→ 源码态只读查看——**这正是「全文查看」价值的场景**。

### 3.3 服务端

- POST /wf/instance-yaml 零改动（语义校验关口、errors 非空不落盘、权限矩阵均既有）。
- GET 响应若无 `text` 字段则补（读取逻辑已有：`stripInstanceHeader(rawFile)`）。
