## 2. 验收发现与处置

### 2.1 立即问题（本轮已修复，v0.29.2）

**#1 硬编码路径排查**
- **排查结论**：全仓（code/ 含包/插件/共享/脚本/preset 声明）**零处显式硬编码绝对路径**（`/Users/`、`/home/` 均 0 命中）；
- **但发现等价的隐式硬编码**：`fs.resolve(相对路径)` 在 fs-host 适配层实现为 `nodePath.resolve(p)`——以 **dsh web 进程 cwd（默认工作空间）** 为基准。工作空间/启动位置变化即解析漂移（验收后续问题 #2 的报错 `…/normal_ws/sys-design.yaml` 即此根因）；
- **修复**：新增 `resolveWorkflowPath`（tools-preset，导出复用）——workflowPath 相对路径改**两级链**：当前工作空间 > 插件预置目录（`detectPredefinedRoot`）；全 miss 时报错指向工作空间。落地两处消费点：`loadWorkflowSource`（workflow_begin）+ `/wf/create`。**同时落实了后续问题 #1/#2 的功能诉求**（相对路径支持 + 用户指定的搜索优先级）。

**#2 gate checker 存在性校验缺失**
- **现象**：`quality-gate.checker` 只查空值，填不存在的技能文件也能通过创建；
- **修复**：validate 补 checker 两级链存在性检查（复用 processor 的 `skillRefExists` 同语义实现），错误码沿用 `E-GATE-CHECKER-MISSING`（消息区分「未指定」vs「技能不存在（两级链 miss）: 路径」）；
- **决策修订**：iter27b 时代「checker 文件缺失不入校验（保持启动期报错）」的旧拍板按验收要求废除（注释留痕）。

**验证**：新增 4 单测（假 checker 拦截/真 checker 放行/相对路径命中工作空间/miss 报错指向工作空间），**607 全绿**（603→607）；发行断言过；⓪ 悬空修正再次实战（0.29.1→0.29.2）。
