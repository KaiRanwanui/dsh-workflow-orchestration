## 3. 迭代分组（2026-10-04 用户拍板定稿：资产组并入磨炼主线后重编号，自 G1 起）

### G1 · 逐活动资产磨炼序列（**主线**，Iter-47 起，一活动一迭代）

> **背景（用户拍板）**：sys-design 12 个活动中**只有 design-init 的执行 skill 与门禁检查定义是真实的**；其余 11 个为初版占位。逐活动把 skill 定义与门禁检查定义做实——通过真实任务执行暴露 prompt 构造、参数传递、中断继续等深层问题（O-7 类门禁语义问题在此边跑边修，序列尾部集中收口兜底）。
> **templates / knowledge 并入本组（用户拍板 2026-10-04）**：原 G2 内容在串工作流时一并搞定——每个活动迭代做实 skill 时同步产出该活动的**输出文档模板**（templates/<activity>.md）与所需**方法论资源**（knowledge/）；design-baseline 迭代（Iter-57）承担全链贯通复跑。

**步调与灵活性（用户拍板，硬约定）**：
- 每迭代 = 该活动的「执行 skill 真实跑 → 门禁 skill 真实跑 → 验收关闭」；
- **随时可插入新迭代**（如 Iter-47-2）处置执行中发现的问题（阻塞优先，缺陷/优化分级进 findings/backlog）；
- **次序可调**（按上游产物依赖与发现情况重排，README 表为准滚动更新）；
- 活动上游产物衔接用真实前序 output（不用占位输入），保证暴露数据流问题。
